# Dataset finder

The public [MORVS and Voidly dataset catalog](https://morvs.ai/voidly/datasets.json) is a static, keyless JSON document. Fetch it when answering; do not rely on a remembered entry or count. It is distinct from MORVS's federal data hub and its MCP tools.

## Workflow

1. Fetch the catalog through an available read-only HTTPS tool, such as Claude Code WebFetch or Codex web.run. Search entries by topic, name, ID, and description. Do not invent a catalog search MCP tool; none appears in the 2026-10-25 live 119-tool list.
2. For each relevant entry, record the landing page, JSON endpoint, extra endpoints, description, counts, build date or observed-at time, and stated license or rights. Follow the entry's endpoint and source/provenance links before claiming current coverage. A catalog count is a dated observation, not a live promise.
3. Read license and rights at both catalog and entry level. For entries derived from third-party material, follow upstream terms; a compilation license does not automatically cover raw source data. State attribution and commercial-reuse limits only when verified at the linked terms.
4. For a federal data hub source found through an entity, call `resolve` with a ticker, CIK, or name to inspect the available-in map, then call `dataset_freshness` with `{}` for source-specific cadence, last successful observation, and indexed-content watermark. Do not apply that freshness result to the static catalog entries unless the dataset is actually represented in the returned row.
5. Seven catalog datasets also have MCP tools. The [Drone Register](https://morvs.ai/voidly/drone-register/) (endpoint `https://morvs.ai/drone-register/index.json`) is queried by `drone_company_check` with `{"name":"Company name"}` and `drone_product_lookup` with `{"q":"Model or component"}`, both read from that published file. The [California Data Broker Register](https://morvs.ai/voidly/data-brokers/) (endpoint `https://morvs.ai/data-brokers/index.json`) is queried by `data_broker_check` with `{"name":"Business name"}` or `{"domain":"example.com"}` and `data_broker_diff` with `{"year_a":"2025","year_b":"2026"}`. The [U.S. Forced Labor Company Register](https://morvs.ai/voidly/forced-labor-register/) (endpoint `https://morvs.ai/forced-labor-register/index.json`) is queried by `forced_labor_company_check` with `{"name":"Company or facility name"}` and `forced_labor_source_compare` with `{"source_a":"dhs","source_b":"cbp"}`. The [PFAS Drinking-Water Register](https://morvs.ai/voidly/pfas/) (endpoint `https://morvs.ai/pfas/index.json`) is queried by `pfas_system_lookup` with `{"pwsid":"IA9778054"}`, `{"zip":"51106"}` or `{"state":"IA","name":"Sioux City"}`, `pfas_system_history` with `{"pwsid":"IA9778054"}` and `pfas_rule_impact` with `{"scenario":"if_proposals_final","state":"IA"}`. The [Government Data Demand Register](https://morvs.ai/voidly/data-demands/) (endpoint `https://morvs.ai/data-demands/index.json`) is queried by `data_demand_source` with `{"source":"google"}` (optionally `"period":"2025-H2"`, `"geo":"US"`) and `data_demand_compare` with `{"sector":"carrier"}`. The [License Plate Reader Register](https://morvs.ai/voidly/plate-readers/) (endpoint `https://morvs.ai/plate-readers/index.json`) is queried by `plate_reader_decisions` with `{"state":"TX","vendor":"Flock Safety"}` (also jurisdiction, disposition, subject, year or query filters) and `plate_reader_state_law` with `{"state":"VA"}`. The [Federal Files Register](https://morvs.ai/voidly/federal-files/) (endpoint `https://morvs.ai/federal-files/index.json`) is queried by `federal_file_search` with `{"query":"passport"}` (also agency, recipient, record-flag or exemption filters) and `federal_file_system` with `{"id":"SSA:60-0058"}`. Prefer them over fetching a whole file for a single company, model, business, water system, year pair, source pair, rule scenario or publisher report; a non-match is "not found in the Drone Register", "No registration … matches" or "No reviewed name or alias match …", never clearance and never "not a data broker", and a PFAS result is an EPA UCMR 5 monitoring average compared with the 2024 limits, not a compliance determination or a household tap result.
6. Return only institution-level or aggregate facts. Avoid PII, unsupported accusations, or treating data absence as evidence of no activity.

| Dataset | Best use | Landing / JSON endpoint | Data date and coverage | Rights / upstream terms | Checked on |
|---|---|---|---|---|---|
| Catalog name | Plain-language use | Both clickable links | Explicit date semantics and gaps | Exact catalog or source terms | Access date |

## Worked examples

**Banned-books data.** For “Find a reusable banned-books JSON source”, use WebFetch or web.run to fetch [the catalog](https://morvs.ai/voidly/datasets.json), select its Verboten entry, and open its listed landing page and endpoint. Read the entry's license and source links. Report the current endpoint, its date/coverage, and the stated terms with citations; do not copy a remembered catalog count as live coverage. No MORVS MCP catalog tool is needed.

**Company-linked federal dataset.** For “Which MORVS federal datasets mention Pfizer?”, call `resolve` with `{"ticker":"PFE"}`. Use its available-in map and links to choose datasets, then call `dataset_freshness` with `{}` and match returned dataset rows. If the user also wants a static Voidly dataset, fetch [the separate catalog](https://morvs.ai/voidly/datasets.json) and check that entry's own endpoint and rights. Keep the two coverage systems separate.
